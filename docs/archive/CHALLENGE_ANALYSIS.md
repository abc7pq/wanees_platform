# رفيقك — المرشد الشخصي الذكي التفاعلي
## حل تحدي مسار الترفيه والألعاب — هاكاثون agentX (شريك التحدي: هيئة الترفيه)

---

## 1. ملخص التحدي

**المشكلة:** الزائر في موسم/مهرجان بعشرات الأنشطة يهدر وقته في البحث والتنقل والانتظار. التطبيقات الحالية تعطي الجميع نفس المعلومة، بينما كل زائر مختلف (ميزانية، وقت، مرافقون، مزاج).

**المطلوب:** وكيل ذكاء اصطناعي يرافق الزائر طوال الزيارة:
1. مسار زيارة مخصص من حوار قصير (مزاج، ميزانية، مرافقون، اهتمامات)
2. إعادة ترتيب تلقائية عند تغيّر الظروف
3. بدائل بناءً على الزحام والوقت المتاح
4. موازنة مصلحة الزائر مع مصلحة الموقع (توجيه الحركة للمناطق الأقل ازدحامًا)

**معايير التحكيم:**
| المعيار | الوزن المتوقع | كيف نكسّه |
|---|---|---|
| جودة المسار | عالية | محرك جدولة بقيد حقيقي (أوقات، مسافات، ميزانية) وليس مجرد قائمة توصيات |
| تجربة الاستخدام | عالية | محادثة عربية طبيعية + خريطة + timeline قابل للتعديل بنقرة |
| الاستجابة للتغير | عالية | أحداث لحظية (زحام، تأخير، طلب الزائر) تُعيد حساب المسار فورًا |
| الأثر التشغيلي | **تُهمل غالبًا من الفرق** | لوحة منظّم: خريطة حرارية + قياس توزيع الحركة قبل/بعد توصيات الوكيل |

### المكونات

**أ. وكيل الحوار (Concierge Agent)**
- LLM (عربي ممتاز) باستخراج منظم: `{mood, budget, companions[], interests[], duration, mobility}`
- 4-6 أسئلة قصيرة كحد أقصى، مع قيم افتراضية ذكية — ما نطفش الزائر بنماذج
- لغة: عربي فصيح مبسّط + رجوزات خفيفة بالترحيب (لمسة ترفيهية)

**ب. محرك المسار (Route Engine)** — *هذا ما يميز الحل عن "شات بوت"*
- الخوارزمية: جدولة إدراكية (Greedy + تحسين محلي 2-opt) على قيود:
  - أوقات العروض المتاحة لكل نشاط
  - زمن التنقل بين المناطق (مصفوفة مسافات)
  - سعة الميزانية (أسعار التذاكر)
  - منحنى الازدحام المتوقع لكل ساعة
- دالة التقييم: `رضا الزائر = Σ(interest_match × mood_fit) − زمن الانتظار والتنقل`
- **حد التشغيل:** دالة التقييم تشمل مصطلح توازن الحمل: التوصية تنقص قيمة الأنشطة في المناطق المزدحمة *فوق مستوى تفاوت مقبول* — يحقق معيار الموازنة بلا إفساد التجربة (نستخدم عتبة، ما نحرم الزائر من شيء يريده بشدة)

**ج. وكيل المراقبة وإعادة التخطيط**
- يستهلك أحداث: تحديث ازدحام، تأخير عرض، إلغاء، أو طلب صريح من الزائر
- عند حدث: يعيد الجدولة جزئيًا (يحافظ على الأنشطة المستمرة/المنتهية) ويشرح التغيير بجملة واحدة ("العرض تأخر 30 د، قدمنا لك X ووقفنا Y")
- كل إعادة تخطيط تُعرض كـ diff واضح — الموافقة بنقرة

**د. لوحة المنظّم**
- خريطة حرارية (متوسط كثافة لكل منطقة/ساعة) محسوبة من *جميع مسارات المستخدمين*
- مؤشر الأثر: نسبة الزوار المُعاد توجيههم من المناطق المشبعة، وانخفاض ذروة الازدحام
- محاكاة "ماذا لو": المنظّم يعدّل سعة/عتبة ويرى الأثر

## 3. الديمو — سيناريو العرض (90 ثانية)

**البيانات:** موسم الرياض محاكى — 20-30 نشاطًا حقيقيًا موزعة على 6-8 مناطق (بوليفارد سيتي، الرياض بارك، الدرعية...) بأوقات عروض وأسعار ومنحنيات ازدحام واقعية.

**السكربت:**
1. **(20ث)** زائر: "معي زوجتي وجوّلين صغار، عندي 300 ريال و3 ساعات، نبي شي ممتع مساءً"
2. **(15ث)** الوكيل يسأل سؤالًا أو اثنين (مزاج؟ مغامرات ولا هدوء؟) → يبني مسارًا من 4 أنشطة على خريطة + timeline مع الأوقات والتكلفة
3. **(25ث)** *حدث مفاجئ أثناء العرض:* الزحام يرتفع في منطقة من المسار → الوكيل يقترح بديلًا ويشرح السبب → نقرة موافقة → المسار يتحدث فورًا
4. **(20ث)** ننقل للوحة المنظّم: الخريطة الحرارية تُظهر أن توصيات الوكيل وزّعت الحركة — نُظهر الرقم (انخفاض الذروة X%)
5. **(10ث)** خاتمة: "الوكيل يخدم الزائر والمنظّم معًا"

## 4. خطة البناء (3 أيام)

### اليوم 1 — العمود الفقري
- [ ] نموذج البيانات + كتالوج الأنشطة المحاكى (JSON: 25+ نشاطًا، 7 مناطق، مصفوفة مسافات، منحنيات ازدحام)
- [ ] محرك المسار (scheduler) كوحدة Python منفصلة + اختبارات
- [ ] API: `/profile` (استخراج من الحوار)، `/route` (توليد)، `/events` (إعادة تخطيط)

### اليوم 2 — التجربة والذكاء
- [ ] وكيل الحوار (LLM + prompt عربي + استخراج JSON منظم)
- [ ] واجهة الزائر: محادثة + خريطة (Leaflet/MapLibre) + timeline تفاعلي
- [ ] محاكي الزحام الحي (يولّد أحداثًا زمنية للعرض)
- [ ] تدفق إعادة التخطيط مع شرح diff

### اليوم 3 — اللمسة الحاسمة والتقديم
- [ ] لوحة المنظّم + مؤشرات الأثر التشغيلي
- [ ] صقل السيناريو، تجربة كاملة أ×5
- [ ] فيديو احتياطي للديمو + سلايدات التقديم + تجهيز إجابات لجنة التحكيم

### التقنيات المقترحة
- **Backend:** Python + FastAPI · محرك المسار خوارزمي نقي (لا يعتمد على LLM للحساب — LLM يفهم فقط)
- **LLM:** أي نموذج قوي بالعربي (GPT/Gemini/Claude) عبر API واحد فقط لطبقة الحوار والشرح
- **Frontend:** Next.js أو صفحة واحدة (React + Leaflet) — PWA تعمل على الجوال
- **استضافة:** VPS قائم + Caddy (متوفر عندنا) → رابط مباشر للجنة
- **Fallback:** فيديو مسجل للديمو لو تعطلت الشبكة في القاعة

## 5. لماذا نفوز (خطافات التحكيم)

1. **مسار محسوب لا "قائمة اقتراحات"** — قيود حقيقية: أوقات عروض، مسافات، ميزانية، ازدحام
2. **الازدحام كمواطن أول** — معظم الحلول تذكره كملحوظة؛ نحن نبني عليه إعادة التخطيط والموازنة
3. **وجهان للحل** — الزائر يرتاح والمنظّم يرى أثرًا تشغيليًا رقميًا (معيار يهمله الجميع تقريبًا)
4. **الشرح والثقة** — كل تغيير له سبب بجملة واحدة، وكل تعديل بنقرة (تجربة استخدام)
5. **جاهز للتوسع** — الكتالوج والمناطق configurable: نفس المحرك يعمل لأي موسم/مهرجان

## 6. المخاطر
| الخطر | التخفيف |
|---|---|
| LLM بطيء في القاعة | الردود المحسوبة مسبقًا للمسارات الأساسية + fallback |
| بيانات ازدحام غير موجودة | محاكاة واقعية + نقطة معمارية جاهزة لاستقبال live feed (كاميرات/تذاكر/GPS مجهول) |
| وقت قصير | نطاق محكم: 25 نشاطًا تكفي للديمو، لا نبنِ auth/دفع |
