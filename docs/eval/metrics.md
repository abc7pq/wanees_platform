## 1. المقاييس الأربعة لنجاح العرض

| ID | المقياس | التعريف الدقيق | الإشارة القابلة للقياس | عتبة القبول | المصدر |
|---|---|---|---|---|---|
| **Q** | **جودة المسار** | نسبة تلبية المسار لتفضيلات الزائر المصرّحة (مزاج/مرافقون/ميزانية/اهتمامات/وقت) دون خرق قيد، وليس «رضا الزائر» (يحتاج قياسًا ميدانيًا لاحقًا) | `تغطية التفضيلات = |محطات تطابق التفضيلات| / |محطات المسار|` + عدّ خروقات القيود (وقت/ميزانية/مرافقون) = 0 | تغطية ≥ 0.75 · خروقات = 0 على عيّنة الانحدار | `coordinator-eval` (19) |
| **U** | **سهولة الاستخدام** | زمن الوصول من فتح الرابط إلى مسار جاهز، وعدد الخطوات، بلا تسجيل دخول | زمن-إلى-مسار بالثواني + عدد الأسئلة (هدف تصميمي ~30 ثانية / 5 أسئلة) | ≤ 30 ثانية عند عيّنة أجهزة حقيقية (لم يُقاس بعد — خطوة P1 ميدانية 28/11) | شريحة 8 |
| **S** | **سرعة الاستجابة** | كمون الذيل للنقاط الحية، لا متوسط فقط | `p50/p95` على `live/assistant/itinerary/replan` | p95 ≤ 186ms@50 · ≤ 115ms@20 (خط الأساس `0e44106`) | خط الأساس `0e44106` |
| **O** | **الأثر التشغيلي** | تحسّن توزيع الحركة/الذروة واكتشاف الأنشطة الأقل ظهورًا — **مؤشر محاكاة اليوم، ليس نتيجة ميدانية** | `Δذروة الازدحام قبل/بعد` + `نسبة الأنشطة الأقل ظهورًا المُكتشفة` (معادلة إرشادية حالية، عتبة ازدحام محاكية 0.75) | تُقارن عند توفر بيانات ميدانية فقط؛ لا عتبة ادّعاء قبل القياس | شريحتي 9/10 |

> **الخط الفاصل مع C عند Software Architect:** هذا الملف يملك **التعريف والمعادلة والعتبة**. C يملك **آلية القياس الحي** (rolloutStage، لوحة المشغّل) التي تُغذّي هذه الإشارات. لا يملك أيٌّ منا تعريف الطرف الآخر.

## 2. مقاييس مستوى الوكيل (عقد emission)

كل استدعاء داخل خط وكيل→محرّك→منسّق يُصدر سجلًا مُهيكلًا لا نثرًا:

| الحقل | المعنى | مثال |
|---|---|---|
| `trace_id` / `span_id` | تتبّع نهاية-لنهاية عبر الحدود | `t_9f2…` / `s_a1b…` |
| `latency_ms` | زمن الاستدعاء | `143` |
| `tokens_in/out` | عدّ الرموز (مسار LLM فقط) | `1240 / 86` |
| `cost_usd` | التكلفة المقدرة | `0.0012` |
| `confidence` | ثقة الوكيل في المخرج | `0.91` |
| `error` / `status` | خطأ مُصنَّف + حالة | `weather_source_timeout` / `degraded` |
| `tools` | الأدوات المستدعاة | `["getWeather","replan"]` |
| `grounding` | هل المخرج مؤرَّض من سياق مزوَّد؟ | `grounded` \| `abstain` |

- **التخفيض المسموح:** ضغط سياق بشرط الحفاظ على الحقول الإلزامية؛ وإلا توقّف وصعّد — لا اقتطاع صامت.
- **المسار التهذيبي:** أساسي → بديل مُضيَّق → قاعدة حتمية → بوابة بشرية (نفس دلالات `2d9ea80`).

## 3. عتبات التدريج (10 → 30 → 60)

| المرحلة | `rolloutStage` (= `overallStage`) | الشرط للترقية | بوابة |
|---|---|---|---|
| **10%** | `10` | خضراء انحدار (Q/U/S على عيّنة ثابتة) + p95 ضمن الأساس | بوابة رجعية CI |
| **30%** | `30` | Q/U/S مستقرة على 10% + صفر خروقات قيد | مراجعة بشرية |
| **60%** | `60` | O يُقاس ميدانيًا (لا يُفترض) قبل الادعاء | بوابة بشرية + بيانات ميدانية |

> `rolloutStage` إسقاطٌ على `SuccessStage`/`overallStage` (نفس enum `60|70|80` في المحرّك `packages/engine/src/eval.ts`) — لا نوع جديد، حتى لا ينفصل القياس الحي عن تقييم المحرّك بقيمتين متناقضتين. القيم كـ config صريح في البيئة، لا ثوابت سحرية في الكود.

## 4. قاعدة منع الاختلاق (ترتبط بـ E1/E2 عند Prompt Engineer)

1. حقل سعر/ساعات/توافر غائب عن السياق المزوَّد ⇒ `grounding:"abstain"` — لا اختراع.
2. أي ادعاء أثر (ذروة، توزيع، اكتشاف) بلا قياس ميداني يُصنَّف «مؤشر محاكاة» ويُكتب كذلك في الواجهة واللوحة.
3. الأرقام المنشورة في العرض تعود إلى عدّ اختبار أو إشارة مُقاسة — قائمة ثابتة في M2 (خط الأساس) أدناه عند تسليم أرقام Backend Architect.
