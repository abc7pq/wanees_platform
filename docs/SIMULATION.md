# حزام المحاكاة المقارنة + مصدر بيانات الزحام (فجوتا wanees2 ١+٢)

يسدّ هذا الملف بندَين من قسم «الخطوة الجاية» في العرض (ص11) لم يكُن لهما تسليم سابق:

- **ص11 «نختبر بالمحاكاة: نقارن التوصية بتوجيه الزائر للمكان الأقل ازدحامًا»** → حزام محاكاة حتمي يقارن توصية المنسّق مع خط الأساس الساذج.
- **ص10/11 «ربط بيانات الزحام الفعلية»** → واجهة `CrowdDataSource` قابلة للاستبدال + مصدر حتمي يقف مكان البوابات/العدّادات الحية.

كل شيء **حتمي بلا LLM وبلا شبكة وبلا `child_process`** — يشغّله `node` مباشرة.

## المكوّنات

| الملف | الدور |
|---|---|
| `engine/crowd-source.ts` | `CrowdDataSource` (واجهة الاستبدال) + `SimulatedCrowdSource` (مصدر حتمي مُبذَّر) + `mulberry32` |
| `engine/simulate.ts` | `runStrategy` (خط أساس «الأقل ازدحامًا» / منسّق) + `compareStrategies` (مقارنة + عتبات قبول) |

| `packages/contracts/src/index.ts` | عقود النقل: `CrowdDataSourceContract` + `SimulationScenarioContract` + `SimulationComparisonContract` |

## التِماس (٢) — مطابق لتماس الطقس (د)

`coordinatorPlan(site, minute, { crowd })` و`computeZoneLoads(site, minute, crowd)` يقبلان معامل `crowd`
اختياريًا. **بلا مصدر = نفس سلوك المنسّق السابق حرفيًا** (توافق إصدار، مثبت بالاختبارات الـ23 القائمة).
بحقن مصدر = يقرأ الازدحام من المصدر بدل نموذج الموقع المدمج.

```
coordinatorPlan(site, minute, { crowd: source })   // مصدر حي / محاكى
coordinatorPlan(site, minute)                       // السلوك السابق (نموذج الموقع)
```

عند توفّر القياس الميداني لاحقًا، يُستبدل `SimulatedCrowdSource` بمصدر يقرأ البوابات/العدّادات الفعلية
دون تغيير أي مستهلك.

## خط الأساس مقابل المنسّق (١)

- **`least_crowded`**: طمّاع يختار المنطقة الأدنى ازدحامًا حاليًا (بلا أي وزن آخر).
- **`coordinator`**: يُعيد استخدام `diversionTargets` الحقيقي من (ج) — نفس المنطق الذي يوجّه الزائر فعليًا
  (سعة استيعاب ×70 + جوهرة مخفية ×20 + انخفاض زحام ×10) — عبر تِماس `crowd`. **لا منطق جديد مبعثر**.
- **مسار هابط**: لو كل المناطق فوق العتبة، يسقط المنسّق إلى «الأقل ازدحامًا» (مضمون الحتمية).

## عتبات القبول (تُقيَّم في `compareStrategies.acceptance`)

| المعيار | الشرط | المعنى |
|---|---|---|
| موازنة الحمل | `coordinator.loadBalancePct ≥ baseline − 5` | المنسّق لا يجعل الازدحام أسوأ |
| الانتظار | `coordinator.avgWaitMin ≤ baseline + 1د` | لا انتظار أسوأ بأكثر من دقيقة |
| كشف الجواهر | `coordinator.gemUtilization > baseline` | المنسّق يوجّه نحو الجواهر المخفية أكثر |
| الفائض | `coordinator.overflow ≤ baseline` | لا زوار متعذّر توجيههم أكثر |

`winner` ميداني بمعيار الانتظار وحده؛ **القبول هو البوابة الفعلية** (متعددة الأبعاد).

## النتيجة المرجعية (seed=20261122, 90د, 35 وصول/د)

| الاستراتيجية | avgWait | loadBalance | gems |
|---|---|---|---|
| الأقل ازدحامًا | 0.34د | 100% | 51.4% |
| المنسّق | 0.99د | 100% | 63.6% |

الخلاصة الصادقة: المنسّق لا يهزم «الأقل ازدحامًا» على الانتظار الخام، بل **يقايض انتظارًا هامشيًا
(+0.65د) بمقابل كشف جواهر أعلى (+12 نقطة)** — أي «يوازن بين راحة الزائر ومصلحة الموقع» كما في العرض،
ضمن عتبات القبول. لا يُدّعى فوزٌ على كل المحاور.

## مسرح الحركة (Crowd Theater) — `/ops/theater`

عرض مرئي للمقارنة: **نفس الزوار، نفس الليلة، نفس التأخير — مع ونيس وبدونه**، جنبًا إلى جنب.

| الملف | الدور |
|---|---|
| `packages/engine/src/theater.ts` | محاكاة حتمية قائمة على الزوار (`runCrowdTheater`): مواقع وحالات كل زائر دقيقة بدقيقة + المؤشرات |
| `packages/engine/src/theater-test.ts` | الحتمية، تطابق العالمين عند ٠٪ استخدام، أثر التأخير، الحضور، الحدود (`npm run test:theater`) |
| `app/app/ops/theater/` | الصفحة: لوحتان متحركتان، زر «انشر التأخير»، شريط زمن، نسبة الاستخدام ونسبة القبول، والنتيجة |

**النموذج**

- المناطق من الكتالوج المنشور؛ طاقة كل منطقة تقديرية = ١٫٥× متوسط الطلب موزعة حسب عدد الأنشطة.
- بدون ونيس: الزائر يختار التالي حسب الشهرة والقرب، ويعرف بالطابور والتأخير لما يوصل؛ نصفهم يتركون طابورًا فوق ٢٥ دقيقة.
- مع ونيس: نسبة `adoptionPct` من نفس الزوار يوزنون الاختيار بالانتظار الحي. عند نشر تأخير العرض يصلهم الموعد الجديد، واللي واقف أو ماشي للعرض يجيه بديل قريب من `diversionTargets` (منسّق الحركة نفسه) يرجّعه قبل العرض، ويقبله `acceptPct` منهم.
- **ضمان العدالة**: عند ٠٪ استخدام العالمان متطابقان دقيقة بدقيقة (مثبت في الاختبار)، وعالم «بدون ونيس» لا يتأثر بالمنزلقات.

**نتيجة مرجعية** (كتالوج بوليفارد وورلد الحالي، ٦٠٠ زائر، عرض الدولفيناريوم ١٨:٣٠، ٣٠٪ يبونه، تأخير ٢٥ دقيقة يُنشر ١٨:٠٢، استخدام ٤٠٪، قبول ٦٠٪):

| المؤشر | بدون ونيس | مع ونيس |
|---|---|---|
| أكبر تجمّع واقف بانتظار العرض | 173 | 148 |
| متوسط وقوف جمهور العرض | 30.6 د | 21.2 د |
| زوار وقفوا ٢٠ دقيقة أو أكثر | 28.8٪ | 18٪ |
| حضور العرض | 173 | 173 |

كلما نُشر التأخير أبكر وارتفع الاستخدام، كبر الفرق (عند ٧٠٪: التجمّع 124 والوقوف 14 د). هذه محاكاة بنموذج مبسّط، **ليست** قياسًا ميدانيًا؛ الأثر الفعلي يحتاج تجربة في الموقع.

### روابط العرض ووضع القصة

- `/ops/theater?event=<slug>` يشغّل المسرح على كتالوج أي فعالية منشورة (من `/api/events/<slug>`)؛ لو تعذّر التحميل يرجع لكتالوج العرض المحلي ويقولها بوضوح. فعالية بلا عرض تشتغل كمقارنة توزيع حركة بدون تأخير.
- `adoption` و`accept` (نسب بخطوات ١٠٪) و`speed` (١ أو ٢ أو ٤) تُقرأ من الرابط، والمنزلقات تحدّث الرابط، فالرابط المشارك يفتح بنفس الإعدادات.
- زر «القصة كاملة بضغطة»: يشغّل الليلة بسرعة ٢× على الأقل، ينشر التأخير ١٨:٠٢ تلقائيًا، يوقف ١٨:٤٦ ليقارن الواقفين عند العرض، و«كمّل» يكمّل للنتيجة.
- اختبارات المتصفح: `tests/ui/theater.spec.mjs` (القصة على عرض جوال، تطابق العالمين عند ٠٪، الرابط والفعالية المفقودة).

### «لو زاد مستخدمو ونيس؟» ومنتقي العرض

- `adoptionCurve` يعيد نفس الليلة بنسب استخدام ٠٪…١٠٠٪ (مجاميع فقط بلا إطارات، ~٠٫٢ ثانية) بنفس الزوار والبذرة؛ نقطة ٠٪ تساوي عالم «بدون ونيس» حرفيًا، ونتائج المجاميع تطابق التشغيل المتحرك (مثبت في الاختبار).
- `slopePerTenPoints` يحسب ميل المربعات الصغرى لكل ١٠ نقاط استخدام، والصفحة تكتبه كجملة: «كل ١٠٪ زيادة… تقلّل الوقوف نحو X دقيقة». مرجعيًا (تأخير ٢٥ دقيقة يُنشر ١٨:٠٢): نحو ٢٫٥ دقيقة لكل فرد من جمهور العرض ونحو ٥١٠ دقائق وقوف على مستوى الموقع.
- **بصراحة**: بدون تأخير يتسطّح الأثر فوق ~٨٠٪ لأن المستخدمين يتجهون لنفس الأماكن الهادئة؛ الصفحة تذكر هذا تلقائيًا متى ما ارتد المنحنى بعد أفضل نقطة.
- المشغّل يختار العرض (`catalogShows`، الأشهر أولًا) ومدة التأخير (١٠/٢٥/٤٥ دقيقة)؛ الاختيار في الرابط (`show`، `delay`) ويُقفل بعد نشر التأخير.
- لو تأخر `/api/events/<slug>` أكثر من ٨ ثوانٍ ترجع الصفحة لكتالوج العرض وتقولها، بدل «جارٍ التحميل» للأبد.
